Added a design note, `docs/further-background/enrichment.md`, setting out the step between searching and solving which records the information ESGF's search APIs do not publish: how long a dataset's data runs for, in what units and calendar, and where a run branched from its parent. It settles what gets stored and where it comes from (start and end from the filename, which costs nothing; calendar and datetimes from a file header, fetched only where they are needed, which is nowhere for monthly and yearly data), why constraints will ask a catalogue entry for this rather than asking the catalogue, and how a solve reports work waiting to be done rather than filing it as missing data. `Covers` shipped in #69 but has only ever run against a hand-written test catalogue, so the note also records the two ways it changes when it meets real data: a minimum-overlap mode alongside full containment, and an explicit refusal for datasets with no time axis.
