Rebuilt [Covers][esmporium.requirements.Covers] against what real data needs:
`mode="overlap"` for the window an anomaly actually uses, beside the containment
check; padding stated as a [Span][esmporium.datasets.Span] on the dataset's own axis
rather than in fractional years; and nothing defaulted, so `align`, `mode` and `pad`
are stated every time.

- A constraint which cannot answer now says so as an outcome:
  [NeedsEnrichment][esmporium.requirements.NeedsEnrichment] if the facts are not
  recorded yet, [MissingFeature][esmporium.requirements.MissingFeature] if the
  requirement is one we have not built. Those groups land in the new
  [SolveResult.couldnt_answer][esmporium.requirements.SolveResult], so a dataset
  nobody has measured is no longer reported as a dataset nobody published.
- [SolveResult.enrichment_inputs][esmporium.requirements.SolveResult.enrichment_inputs]
  hands back one [EnrichmentInput][esmporium.requirements.EnrichmentInput] per dataset
  and missing fact, deduplicated and shaped to pass straight to an enricher.
- A constraint can refuse the leaf it is attached to as the requirement is built, by
  implementing [ChecksItsLeaf][esmporium.requirements.ChecksItsLeaf]. `Covers` uses it
  to refuse a leaf which can only select data with no time axis.
- `Covers` answers `MissingFeature` when the covering role is not the target's direct
  parent; coverage along a longer chain is not built yet.
