- Queries can now ask for `activity`, `realm` and `resolution`. Every query class
  declares them and the APIs answer, but no [Dataset][esmporium.db.schema.Dataset]
  column holds them, so nothing could match on them until
  [DatabaseCatalogue][esmporium.db.DatabaseCatalogue] began filling
  [CatalogueEntry.project_facets][esmporium.requirements.CatalogueEntry.project_facets]
  from stored search documents. Project-specific facets like CMIP5's `product` come
  with them.
- An entry which does not record a facet a query asks for no longer matches it,
  instead of raising
  [UnrecordedFacetError][esmporium.requirements.UnrecordedFacetError]. The answer
  used to depend on which facet [matches][esmporium.requirements.matches] checked
  first, and so on which rows were present rather than on what was asked.
- A query's facets are split once per lookup rather than per entry
  ([asked_facets][esmporium.requirements.asked_facets],
  [matches_facets][esmporium.requirements.matches_facets]), keeping the facets we
  model apart from [Query.other_terms][esmporium.query.Query.other_terms], which are
  never translated.
- [Requirement.cardinality][esmporium.requirements.Requirement.cardinality] is now a
  [Cardinality][esmporium.requirements.Cardinality] enum. It subclasses `str` with the
  same values, so passing or comparing `"one"` and `"all"` still works.
- Importing [esmporium.db][] no longer pulls in the whole of [esmporium.search][]:
  [esmporium.db.schema][] imports [esmporium.search.health][] only under
  `TYPE_CHECKING`.
