[download_files][esmporium.downloads.download_files] and
[download][esmporium.db.download] now take `max_workers`, to fetch several files at
once. No more than `per_data_node` transfers run against any one data node, so a run
does not get itself rate limited, and a file which failed for a reason that might not
recur is tried again before the run ends (`requeue_passes`). A file being fetched
right now is recorded as `RUNNING` ([esmporium.db.DownloadStatus][]), so what is in
flight is a question the database answers. Two requests in one batch which would
write to the same path now raise
[DuplicateDestinationError][esmporium.downloads.DuplicateDestinationError],
because fetching them at once would leave neither file intact.
