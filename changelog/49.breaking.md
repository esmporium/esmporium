- Moved the reading of how many records matched a search from the result parsers
  onto the search APIs, as
  [SearchAPI.get_n_matches][esmporium.search.apis.SearchAPI.get_n_matches].
  Both ESGF-NG deployments now report the count as `numberMatched`,
  so where the count is written is a property of the format an API speaks
  (Solr writes it at `response.numFound`, STAC at `numberMatched`)
  rather than a choice an individual endpoint makes.
- Removed the `read_n_matches` argument of [fire][esmporium.search.fire].
  `fire` is already given the API it is sending to,
  so it now reads the count off that rather than being handed a reader as well.
