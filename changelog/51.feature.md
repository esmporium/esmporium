Added [DatabaseCatalogue][esmporium.db.DatabaseCatalogue], a
[Catalogue][esmporium.requirements.Catalogue] backed by esmporium's own database, so
[solve][esmporium.requirements.solve] can be run against the
[Dataset][esmporium.db.schema.Dataset] rows a search saved rather than a catalogue
written out by hand. Run the same requirement tomorrow and the difference between the
two [SolveResult][esmporium.requirements.SolveResult]s is what changed.
[find_datasets][esmporium.db.find_datasets] is the same lookup for a caller who wants
one session across a whole solve.

Added [to_search_plan][esmporium.search.to_search_plan], which turns a
[Requirement][esmporium.requirements.Requirement] into a
[SearchPlan][esmporium.search.SearchPlan]: one
[LeafSearch][esmporium.search.LeafSearch] per distinct query the tree asks for, each
being the leaf's query with the requirement's `where` added, deduplicated so two roles
asking for the same dataset are searched once. It is the same query
[solve][esmporium.requirements.solve] later matches against, so searching and solving
cannot drift apart. [plan_sub_searches][esmporium.search.plan_sub_searches] then
splits each across the projects its query names. Together these close the gap between
[esmporium.search][] and [esmporium.requirements][]: a requirement can be searched for
against the live APIs and then solved against the database.

Also added:

- [Requirement.versions][esmporium.requirements.Requirement.versions]
  ([VersionFilter][esmporium.requirements.VersionFilter]), which says which of a
  dataset's stored versions count. The default excludes datasets whose only versions
  were retracted, and the setting also picks which version's documents describe an
  entry.
- [group_by_other_terms][esmporium.requirements.Requirement.group_by_other_terms] and
  [prefer_other_terms][esmporium.requirements.Requirement.prefer_other_terms], for
  grouping or breaking ties on a facet only a search document knows. Never translated
  and never checked, so the name must be spelled as the document spells it, and
  applied after their modelled counterparts. `group_by` and `prefer` themselves are
  now checked when a requirement is built, raising
  [UnmodelledFacetError][esmporium.requirements.UnmodelledFacetError].
- [UngroupableFacetError][esmporium.requirements.UngroupableFacetError],
  [UnrankableFacetError][esmporium.requirements.UnrankableFacetError] and
  [MixedProjectFacetError][esmporium.requirements.MixedProjectFacetError], raised when
  a facet is fine as a name but the data cannot answer it: nothing records it, or it is
  project-specific and the group spans projects.
- [esmporium.datasets][], the vocabulary about a stored dataset that
  [esmporium.db][], [esmporium.search][] and [esmporium.requirements][] must agree on,
  starting with [DATASET_FACET_COLUMNS][esmporium.datasets.DATASET_FACET_COLUMNS].
