Added [esmporium.headers][] and [esmporium.db.build_header_facts_provider][], which
read a dataset's parent out of its files' own headers. This is the `facts_provider`
that [find_parents][esmporium.db.find_parents] asks for, so a CMIP5 or CMIP6 parent
walk now works -- neither project publishes a parent anywhere a search can see it. One
HTTP range request fetches about 64 KiB from the start of one file, so nothing is
downloaded. Classic netCDF is read with nothing installed; netCDF-4/HDF5, which is all
of CMIP6, needs the new `headers` extra (`pip install esmporium[headers]`).

- One read answers a whole simulation, because a parent belongs to the run and not to
  the variable, so a simulation's other datasets take their facts from the same file.
  [esmporium.db.plan_header_reads][] says what a walk will take before it is run.
- [esmporium.db.HeaderReadCallRecord][] records one row per attempt with its
  [esmporium.datasets.HeaderReadOutcome][], and
  [esmporium.db.build_header_read_health_selector][] prefers the data nodes which have
  answered before. A node that is unreachable or hanging is dropped for a file's
  remaining routes rather than costing a timeout on each of them.
- [esmporium.db.DatasetVersionParent][] gained `branch_time_in_parent` and
  `branch_time_in_child`, stored exactly as the file published them. CMIP5's
  `branch_time` cannot be interpreted -- the same attribute carries years, calendar
  years, `YYYYMM`, `YYYYMMDD` and days since an unstated origin -- so it is recorded
  as what a file said rather than as a time.
- Added [esmporium.fixes][] for the runs whose headers cannot name their parent
  however well they are read. [esmporium.fixes.PARENT_FIXES][] holds the three CMIP5
  simulations which name their parent experiment but not its variant, each with its
  evidence, and a fix is recorded beside what the file said rather than instead of it.
