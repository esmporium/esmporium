Added [esmporium.downloads][] and [esmporium.db.download][], which fetch the files a
query asks for from the ESGF data nodes and record what came of it.
[download][esmporium.db.download] plans, queues, fetches and records in one call,
taking the same query object a search takes. One row is written per file as that file
finishes, so an interrupted run keeps what it already has, an interrupted transfer
leaves a `.part` which the next run continues with a `Range` request, and a file
already on disk at the right size is not fetched again.

- [esmporium.db.Download][] holds where each file has got to
  (`QUEUED`/`RUNNING`/`DONE`/`FAILED`/`GIVEN_UP`), so what is outstanding is a
  question the database answers. [esmporium.db.download_summary][] is the headline.
- [esmporium.db.DataNodeCallRecord][] records one row per fetch attempt, with
  throughput. [esmporium.db.build_data_node_health_selector][] ranks data nodes by
  reliability first and throughput second, and
  [esmporium.db.build_refreshing_data_node_health_selector][] re-reads that health on
  a timer, so a long download moves away from nodes that go bad while it is running.
- [esmporium.datasets.DownloadOutcome][] says how one attempt turned out. `MISSING`,
  `NEEDS_CREDENTIALS` and `SIZE_MISMATCH` are not held against the data node: a
  recorded route can stop existing, we fetch anonymously, and ESGF sometimes
  publishes a size that the file it serves does not match.
- There is no default ranking of data nodes, because which nodes hold a given file
  varies per file.
  [DEFAULT_DATA_NODE_SELECTOR][esmporium.downloads.DEFAULT_DATA_NODE_SELECTOR] only
  drops routes we cannot fetch and prefers HTTPS;
  [build_data_node_list_selector][esmporium.downloads.build_data_node_list_selector]
  takes your own ranked list.
