# Results → database: what still needs to change

`schema.py` now has the tables for storing ESGF search results
(CMIP5/6/7, Solr and STAC). This note lists everything **else** the repository needs
for those tables to actually be populated and tested. It is deliberately deferred:
none of it touches `src/esmporium/search/`, which is being reworked on another branch.

## What already landed (in `schema.py`)

- `Dataset.id` — primary key, built from the facet columns (includes the variable),
  so it is unique per row even for CMIP5.
- `Dataset.id_project_specific` — **indexed, not unique**: a grouping key = "which ESGF
  dataset this row belongs to" (shared across a CMIP5 dataset's variables).
- `Dataset.grid_label` — nullable (NULL for CMIP5).
- `DatasetVersionSpecific` — one row per edition; PK `version_id = f"{dataset.id}.v{version}"`.
- `DatasetAccessInformation` — one row per (version, data node); unique `(version_id, data_node)`.
- `DatasetRawDoc` — the raw doc, deduped by `esgf_doc_id`, linked to the version by a
  **direct FK** (no `data_node` column — recover it from `esgf_doc_id` for Solr).

```
DATASET ─1:*─ DATASET_VERSION ─┬─1:*─ DATASET_NODE   (DatasetAccessInformation)
                               └─1:*─ RAW_RECORD     (DatasetRawDoc)
```

## Downstream changes (roughly in order)

### 1. Alembic migration
Generate a revision with `src/esmporium/db/migrate.py` (autogenerate). It must:
- create `datasetversionspecific`, `datasetaccessinformation`, `datasetrawdoc`;
- drop the old `uq_dataset_id_project_specific` unique constraint and add an index
  (`ix_dataset_id_project_specific`) in its place.
Review the autogenerated ops — Alembic doesn't always emit constraint drops for SQLite cleanly.

### 2. Regenerate the DDL regression fixture ⚠️
`tests/regression/test_schema_ddl/test_schema_ddl.sql` is a snapshot of the emitted DDL
(`tests/regression/test_schema_ddl.py` builds the DDL from `METADATA`). **Until it is
regenerated, that test WILL FAIL** — expected, not a real regression. Regenerate with
`pytest --force-regen` (pytest-regressions), review the diff (three new tables + the
`unique → index` change on `dataset`), and commit it.

> Note: the whole test suite currently can't even be collected on this branch, because
> `from esmporium.db import METADATA` pulls in `esmporium.search`, which is non-importing
> mid-rename (the colleague's branch). Once that imports again, run the tests below.

### 3. Ingestion script — `scripts/search_results_to_database.py` (new)
Hand-run and visual, in the style of `scripts/cmip5_results_to_dataset.py`.

- **Detect shape from the response, not the project:** `response.docs[]` ⇒ Solr,
  `features[]` ⇒ STAC. (CMIP6 can come back either way.)
- **Per doc → rows:**
  - `Dataset`: build `id` with the constants already in
    `scripts/cmip5_results_to_dataset.py` (`ID_COLUMN_ORDER`, `GRID_LABEL_PLACEHOLDER="0"`,
    `DRS_MODEL_INDEX=3`). For CMIP5, confirm the searched variable is in the doc's
    `variable` list and take **only** that variable.
  - `DatasetVersionSpecific`: upsert on `version_id`; **refresh** `is_latest`/`retracted`
    (they are search-time snapshots that flip over time).
  - `DatasetAccessInformation`: upsert on `(version_id, data_node)`.
  - `DatasetRawDoc`: **get-or-create by `esgf_doc_id`** so the JSON is stored once.

### 4. Search-facade contract (do NOT edit `src/esmporium/search/`)
The ingestion consumes the search layer owned by the colleague's branch. Assumed interface:
- `esmporium.search.search(...)` returns a `SearchOutcome` whose `results` dict is keyed by
  host, each value the raw JSON that host returned.
- Which facade/generation produced each result is knowable (facade carries `source_api` /
  host); ingestion records it on `DatasetRawDoc.source_api` + `search_host`.
- Raw JSON is passed through untouched (no canonical translation) for `raw_json`.
Confirm/adjust once that branch merges.

### 5. Deferred: `RAW_LINK` (CMIP5 multi-variable only)
Needed only when >1 variable is ingested from one CMIP5 dataset, where one raw doc
describes several per-variable versions (many-to-many). Then:
- add a `(raw_id, version_id)` junction table (unique on the pair);
- move the link off `DatasetRawDoc.version_id` into it.
Additive — does not disturb `DATASET`/`VERSION`/`NODE`. Not needed for the tas-only search.

### 6. Tests to update / add — `tests/unit/test_schema.py`
- **Replace `test_id_project_specific_is_unique`** — it asserts the OLD unique contract and
  will now fail. Rewrite it as its opposite: two `Dataset`s with **different `id`** but the
  **same `id_project_specific`** must commit successfully (the CMIP5 multi-variable case).
- Still valid, leave as-is: `test_id_is_unique` (PK), `test_facets_are_not_unique`,
  `test_facet_columns_are_the_declared_facets` (id and id_project_specific are excluded
  from facets, and facets are unchanged).
- **Add** for the new tables: FK integrity across all four, `esgf_doc_id` uniqueness (a
  unique *index*, `ix_datasetrawdoc_esgf_doc_id`), and the `(version_id, data_node)` unique
  constraint on `DatasetAccessInformation`.
- Parsing: drive per-generation parsers from the recorded fixtures in
  `tests/test-data/search/` (Solr CMIP5/CMIP6, bridge CMIP6, STAC CMIP6/CMIP7).

### 7. Small helper
A function to recover the data node from a Solr `esgf_doc_id`
(`esgf_doc_id.rsplit("|", 1)[-1]`; STAC ids have no `|`).
